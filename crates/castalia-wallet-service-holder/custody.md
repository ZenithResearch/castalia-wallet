# Native service custody

The native owner can now create, open, configure, rotate, revoke and reconcile a dedicated service identity in an explicitly selected private directory. The store uses an OS-random raw32 Ed25519 seed, separate from Member Key/encrypted extension custody and recovery. These are Rust owner-administration APIs, not browser, RPC, executor or arbitrary signing methods. No live identity has been provisioned by this implementation.

`ServiceIdentityStore::create(path, NewServiceIdentity)` requires a pre-existing canonical private 0700 root. Select the root in owner startup code; never take it from request or proof wire. Only `runtime` and `service` applications are accepted. Creation returns an unconfigured store and public `StoreBinding`. Preserve the binding independently; it fixes store ID, subject, application, purpose and minimum revision. `public_identity()` returns public metadata; `expected()` provides the exact revision/digest CAS value for mutations. The native owner is the administrative boundary, not the public CAS token.

A store starts at revision/generation 1. `configure(expected, exact_owner_bytes)` requires the complete independently authored existing Wallet owner-input format, matching the generated public key, subject, key generation, validity, application and **next** state revision. The library does not rewrite delegation rules for a new key. Full descriptor obligations/mode are inspected; every nonempty unsupported requirement denies. Configuration stores exact owner bytes and their hash and creates an active storage state. It does not qualify those bytes as execution authority. `open_identity(expected)` returns a non-Clone opaque current handle only for an active live state. The legacy caller-owner/caller-clock challenge methods remain denied. The new `present_current_service_challenge` derives its owner policy and OS time from actual retained custody and signs only the frozen compact holder proof. Its signature authenticates opaque issuer evidence bindings, not independently current Native evidence or execution authority. Actual current Native producer/completion integration and installed admission remain separate. No raw seed, signing key or arbitrary sign callback is exported.

`rotate(expected, start, end)` generates a new seed, preserves the stable subject, increments generation/revision, and returns to unconfigured. `revoke(expected)` is terminal; the current revoked revision contains no seed or owner-input file. Public diagnostics remain readable after expiry/revocation. Old receiver proofs require receiver-side revocation/current-registry handling; local deletion is not remote revocation.

## Publication, recovery and limits

Each immutable revision is a bounded `states/s<16 decimal digits>` directory. CURRENT binds its revision and canonical state SHA. CLOCK binds the store ID and last durable observation. Seed/public-key/fingerprint/key-ID consistency is verified under every lease. Metadata has exact required fields, sorted compact UTF8 JSON and unsigned safe-integer lexemes; unknown/duplicate/omitted nullable fields, aliases, negative zero, exponents, floats and Serde's reserved number-map representation deny. Public application request bytes and native wire formats are unchanged. The public metadata schema/vectors are in `tests/custody-vectors`.

A writer uses a process-registry permit plus a separately opened nonblocking OS flock. Store instances pin the stable lock inode across operations; leases retain verified ancestor/root descriptors. Each mutation requires exact CURRENT CAS, rechecks its predecessor immediately before publication, syncs a complete immutable revision, publishes CLOCK before CURRENT, atomically publishes CURRENT, rereads all selected bindings, and checks native time after blocking I/O. Any uncertain publication poisons the process epoch and returns `PublicationUncertain`; never retry a rotation blindly.

`reconcile_current()` validates and syncs only the CURRENT actually selected on disk, publishes a new durable clock observation, and invalidates prior handles even if CURRENT did not change. It never falls back to an older revision. `open(path, binding)` is a checked reload and also invalidates handles in the same process. `cleanup_unreferenced(expected)` explicitly removes bounded known retired/staging files, preserves CURRENT, updates CLOCK, and invalidates handles. Invoke cleanup before another mutation when a retired or staging candidate remains. No open operation silently cleans or creates files.

If first-create acknowledgment was lost, `recover_initialization(path, original_spec)` may recover only an exact valid revision1/generation1/unconfigured CURRENT with matching actual seed and durable CLOCK, without generating entropy or selecting an orphan. If CURRENT is absent, `OwnerConfiguredRoot::open(path)` followed by `inspect_initialization(&root, original_spec)` returns a non-Clone inspection that **retains its exclusive lease** until dropped or consumed by `inspection.abandon()`. It can remove only safe recognized incomplete revision1 state, never any present CURRENT. Abandonment preserves the lock inode and leaves an empty RESET marker; a separate explicit create consumes RESET. This retained-lease API eliminates an inspection-to-abandon reopening gap.

The unchanged accepted filesystem layer limits seed/state/owner files to 32/4096/262144 logical bytes, CURRENT/CLOCK to 512/256, and counts allocated blocks as well as logical lengths. It bounds entries/revisions, rejects unknown names, follows no symlinks, rejects hardlinks/unsafe ACLs/modes/owners, and reserves physical growth within 4 MiB. Lock/RESET must have zero allocated bytes. Native local filesystem durability and cooperative writers are required; unsupported filesystems fail closed. Existing generic read/Output consumers are not rerouted.

The clock detects rollback against the last durable observation and a shared store high-water mark and a process-wide native-clock floor that survives closing all store handles. Starts may be zero; observations are positive; ends are exclusive. Final observation can be later than the last fsynced floor. A restored entire store or malicious owning UID cannot be detected without an independent anchor. Advisory locking and raw files do not defend against the owning UID/root ignoring the protocol. Deleting retired files does not securely erase APFS/SSD snapshots or backups.

## Verification and remaining boundary

Run the supported commands in README. The same production filesystem/lifecycle source is exercised by disposable native store tests, including OS entropy, crash-process exits, lock contention, stale CAS, lost initial acknowledgment, clock rollback, metadata hostility, key mismatch and final checks. Test-only clocks, failure hooks and synthetic signing are `cfg(test)` only. The separate private-files package tests retain the low-level path, lock, allocation and write/sync fault coverage. No test changes live custody or trust.

Current-custody holder signing now has a bounded source implementation; current Native issuance/completion integration, receiver registration/current policy, installed artifact qualification and operational rollout remain open. Zero production descriptors are qualified by the empty-obligation fixtures. A holder proof does not issue a verified execution context or complete Gate 1.
